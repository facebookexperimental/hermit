## In short

Natively, a futex wait sleeps in the host kernel until another thread wakes it, its timeout expires on host time, or a signal arrives, so who runs next follows host scheduling. Hermit instead keeps waiters in its own scheduler in arrival order and ends timed waits at a logical deadline, so the same schedule wakes the same waiters. The priority-inheritance protocol is replayed against that modeled queue rather than left to the host kernel, and a robust owner's death marks each still-owned plain word before waking one waiter if the word still shows waiters, wakes a pending word that no longer names an owner without marking it, and leaves a PI word's successor to the PI owner-death hand-off rather than waking it in the walk. Known gaps: 12.

## Determinism strategy

**What is nondeterministic natively.** `futex` waits on, wakes, moves, or locks waiters on a word in guest memory, so whether a wait blocks, which waiters a wake takes and in what order, when a timeout expires, and whether a signal ends the wait all depend on host thread scheduling and host clocks.[^linux] The priority-inheritance forms add owner and waiter state in the word itself, and a robust owner's death must mark its words and wake a waiter, so thread exit timing is guest-visible through this call as well.[^linux]

**What Hermit does.** Detcore determinizes `futex` in its default precise mode by emulating the call against a modeled waiter pool in its deterministic scheduler without running the modeled wait in the host kernel: typed dispatch reaches a handler that keys each word, compares it for the waits, and parks, wakes, moves, or hands over waiters only at scheduler turns.[^c1][^c2][^c8] A private word is keyed by its address space and address and a word in a tracked shared mapping by its backing object — a flagless operation on any other word takes the private key too (G10) — so threads sharing an address space or a mapping wait on the same modeled futex and unrelated processes do not, and a shared key is used only after the kernel is asked to admit it, except on the wait path and for the robust owner-death wake, which take their key directly from the address and ask for no admission.[^c27][^c36][^c26][^c8][^c40] A wait whose word no longer holds the expected value fails at once, and one that parks ends only when a modeled wake takes it, a signal ends it under the restart rules below where the backend declares it can interrupt a blocked wait or the in-guest delivery gate applies (G12), or its deadline passes: a plain wait's relative timeout is added to observed logical time and a bitset wait's absolute deadline is taken on the logical clock when time is virtualized.[^c9][^c10][^c11][^c46] In the default mode, wakes take the longest-waiting matching waiters first and keep the rest in arrival order, and the same pool serves requeues, which wake some waiters and move the next ones onto the second word in order.[^c16][^c17][^c35][^c45] The priority-inheritance lock commands run the kernel's word protocol as decisions over the word and the scheduler's record of its owner and queue, with waiters handed the lock in arrival order and no priority boosting, which matches the order for ordinary tasks that are neither realtime nor deadline-scheduled.[^c19][^c31] When a robust owner dies, Detcore replays the owner's list walk against the modeled pool: for a still-owned plain word that still shows waiters it wakes one plain waiter on the word's modeled key only after the owner-died word change — where the native exit also walks the list, Linux makes that change and Detcore only supplies the modeled wake, and only where no native walk runs does Detcore mark the word itself first — while a pending entry whose word no longer names an owner wakes one plain waiter with no marking at all, and a PI entry is marked in the walk but not woken there, because the separate PI owner-death path hands the lock to its longest-waiting PI waiter still able to take it, which writes its own identity into the word with the owner-died and waiters marks when it runs.[^c22][^c32][^c43][^c44] Apart from a null-word wait, which is injected into the host kernel,[^c39] only the opt-in polling and external debug modes, and runs without sequentialized threads, leave any part of the wait to the host kernel instead.[^c7]

**Interface fidelity.** The commands are honored exactly where Linux's dispatcher honors them: `FUTEX_WAIT`, `FUTEX_WAIT_BITSET`, `FUTEX_WAKE`, `FUTEX_WAKE_BITSET`, `FUTEX_REQUEUE`, `FUTEX_CMP_REQUEUE`, and `FUTEX_WAKE_OP`, and the four lock commands `FUTEX_LOCK_PI`, `FUTEX_LOCK_PI2`, `FUTEX_TRYLOCK_PI`, and `FUTEX_UNLOCK_PI`, are emulated, each with or without the private flag.[^c4][^c5][^c6][^linux] An unknown command, the removed `FUTEX_FD` form, and the `FUTEX_CLOCK_REALTIME` flag on any command but `FUTEX_WAIT_BITSET`, `FUTEX_WAIT_REQUEUE_PI`, and `FUTEX_LOCK_PI2` are answered with `ENOSYS` as soon as the command is classified, before the address or a timeout is looked at, while `FUTEX_WAIT_REQUEUE_PI` and `FUTEX_CMP_REQUEUE_PI`, which would move condition-variable waiters onto a PI mutex, are refused by name with no fallback inside the call; user space that waits on its own word and then locks the mutex, as modern condition variables do, is served by the plain commands above.[^c3][^c4][^c29] Each argument check matches Linux's on its own, but not their order when two fail at once (G11): a misaligned word fails with `EINVAL` before a wait's timeout is examined, a wait then validates its timeout and refuses a zero bitset with `EINVAL` before reading the word with the guest's own permissions, an unreadable word fails with `EFAULT`, and a changed word fails a wait or a comparing requeue with `EAGAIN` without parking or moving anyone.[^c13][^c30][^c26][^c9][^c17] A wake keys its word without reading it, takes only waiters whose bitset intersects the wake's, wakes one waiter for a count of zero or below, and stops with `EINVAL` at a PI waiter after waking those before it. A requeue instead wakes up to the count in `val`, moves up to the count carried in the timeout slot onto the second word behind the waiters already there, and returns how many it woke plus how many it moved, ignoring waiter bitsets: either count below zero fails with `EINVAL` before either address is keyed, a wake count of zero wakes nobody, unlike a plain wake, and meeting a PI waiter stops the walk with `EINVAL`, keeping the wakes and moves already made.[^c17][^c45] The wake-with-operation form applies its encoded operation to the second word in the caller's turn and compares the value the word held before that operation, failing with `ENOSYS` for an unknown operation before touching it and for an unknown comparison after writing it, waking nobody then; when the comparison is known it always wakes up to the count in `val` on the first word and wakes up to the timeout-slot count on the second word only when that old-value comparison holds, ignoring waiter bitsets on both, with a count of zero or below still waking one as a plain wake does, and stops with `EINVAL` at a PI waiter on either word after the operation, keeping the wakes already made.[^c15][^c18] Timeouts keep their Linux shapes: no timeout pointer waits without a deadline, the plain wait's timespec is relative, the bitset wait's and the PI locks' are absolute on the monotonic clock unless the realtime flag or `FUTEX_LOCK_PI` puts them on the realtime clock, an invalid timespec fails with `EINVAL`, and a wait that reaches its deadline fails with `ETIMEDOUT`.[^c11][^c13][^c10][^linux] A signal that ends a parked wait — which it does only where the backend declares it can interrupt a blocked wait or under the in-guest delivery gate (G12) — returns the wait's restart form, which a handler turns into `EINTR` or a restart and which restarts the call when no handler runs, except that a timed plain or bitset wait keeps its first deadline through the restart record and a handler always turns its form into `EINTR`, and a PI lock wait always restarts.[^c14][^c10][^c46] Taking a PI word the caller already owns, or queueing behind an owner who waits through other PI words for a lock the caller owns, fails with `EDEADLK`; a PI trylock that would have to queue fails with `EWOULDBLOCK` instead, a first PI lock whose word names an owner that is no longer alive sets the waiters mark and fails with `ESRCH`, and a PI lock on a word whose first waiter is a plain waiter fails with `EINVAL`. Releasing a PI word that does not name the caller as its owner fails with `EPERM`, while one that names the caller but whose modeled PI state belongs to another owner, or whose first waiter is a plain waiter, fails with `EINVAL`; a contended release writes the next owner's identity into the word and hands it the lock, and an uncontended one clears the word.[^c20][^c21][^c34] The separate sized and vector futex calls are not forms of this call: Detcore answers the whole `futex2` family with `ENOSYS`, as a kernel without it does, so probing runtimes fall back to this call.[^c24][^c25]

**Record & replay.** The call is subscribed in both run and record/replay modes (code facts in the Appendix).[^c2] In the precise model replay needs no recorded futex result: it reaches the same modeled park, wake, move, or hand-over at the same schedule point against the same logical deadline and regenerates the same answer, because, besides a null-word wait,[^c39] the only host futex calls are effect-free shared-key admission probes, which replay asks again rather than taking a recorded answer; a probe interrupted by a signal before it runs is never retried and instead refuses the run by name, since retrying could lose the held signal and admitting the key unchecked could answer wrongly.[^c8][^c11][^c41] The external debug mode is the exception: its host wait goes through the record-or-replay path so replay returns the recorded result, and without sequentialized threads the host call runs with its kernel restart kept.[^c7]

## Known gaps

- G1 (unimplemented): the two requeue-PI commands are refused by name rather than emulated, returning `ENOSYS` where the run is not fail-closed; a guest has no in-call fallback, and only the wait-on-its-own-word then lock-the-mutex protocol that modern condition variables use is served.[^c4][^c29]
- G2 (by design): modeled waiters can only be woken, moved, or handed a lock by guest threads in the schedule: a process outside the run that shares the word is not made deterministic and its host-kernel wake cannot reach a parked modeled waiter, which then sleeps until a guest wake, a signal, or its deadline.[^c8][^c28]
- G3 (by design): a command that changes its word — the wake-with-operation form and the PI lock and unlock forms — refuses a word in a file-backed shared mapping by name, because Detcore's separate read and write could lose an outside writer's update that the kernel's locked instruction would keep; private and anonymous shared words are served, and there is no fallback for a file-backed word.[^c28][^c18][^c21]
- G4 (by design): priority inheritance does not boost an owner's scheduling priority, and modeled waiters — PI lock waiters and plain waiters taken by a wake or a requeue alike — are served in arrival order rather than Linux's priority order, with one qualification: the PI successor at an unlock or an owner's death is the longest-waiting PI waiter that is not already leaving, as a waiter Linux is already removing cannot take the lock either. A guest that relies on realtime priority order, or on deadline order among deadline-scheduled PI waiters, therefore gets the equal-priority order instead; ordinary tasks see the same order Linux gives them.[^c19][^c16][^c45][^c44][^linux]
- G5 (unimplemented): robust owner-death waking covers the modeled exits, group exits, and successful execs the backend reports, but not every death on every backend: on two backends none of these deaths is modeled at all, on another a fatal signal is not yet modeled, and some fatal-signal and exec corners elsewhere walk nothing.[^c37][^c23][^c32] Where a Linux task still exits on those paths, Linux's own exit walk marks each held word owner-died and a later locker sees the mark; only the modeled wake is lost, and the parked waiter sleeps on until another guest wake, a signal, or its deadline, with no guest fallback for the missed wake. Where no Linux task exits and Detcore's own walk is the only one that would mark the word — the Detcore (KVM) path — a death that path does not model is marked by neither walk: the word stays unmarked as well as unwoken, so a later locker does not see owner-died either, and the waiter likewise sleeps on with no guest fallback.[^c23][^c32] The modeled walk also compares each word against the container-namespace thread identity rather than the namespace-local one a guest-created nested PID namespace stores in its lock words, so in such a namespace it finds no owned word and wakes nobody, while Linux's walk still marks the word.[^c38][^c33]
- G6 (unmeasured): when time is not virtualized an absolute deadline is always rebased onto logical time from a clock reading, and when time is virtualized but the guest reads its clock without Detcore the deadline is first judged by which clock it was written against, so a deadline far from both clocks could be judged against the wrong one in that case and expire early or late; virtualized runs whose clock reads Detcore serves take the deadline as written.[^c12][^c11]
- G7 (by design): the polling and external debug modes and runs without sequentialized threads do not keep the modeled guarantee: polling retries the host call without a waiter list, so the requeue, wake-with-operation, and PI lock commands are refused there, and external and unsequentialized waits block in the host kernel whose wake timing is not made deterministic outside record and replay.[^c5][^c6][^c7] The opt-in `--fuzz-futexes` mode also leaves the default wake order: it wakes a shuffled sample of the matching waiters rather than the longest-waiting ones.[^c35]
- G8 (unimplemented): the PI lock and unlock commands are refused by name for a caller in a nested PID namespace, whose PI words hold thread identities Detcore does not translate, returning `ENOSYS` where the run is not fail-closed; the plain wait and wake commands are still served there, and a guest that needs PI locking has no fallback inside such a namespace.[^c33][^c21][^c29]
- G9 (unimplemented): a shared wait does not ask the kernel to admit its key, as the other keying commands do, so a shared word that the guest can read but whose key the kernel would not admit — a word no guest access can read still fails with `EFAULT` before any parking, as on Linux — instead parks in the modeled pool until a wake, a signal, or its deadline ends it, or answers `EAGAIN` at once if that readable word no longer holds the expected value, where Linux refuses the same call at key admission with `EFAULT`; there is no guest-visible signal that the admission was skipped.[^c8][^c26][^c13][^c9][^linux]
- G10 (unimplemented): Linux keys a futex word by the operation's private flag, so a private and a flagless operation on one word never reach each other's waiters, but Detcore keys a flagless operation on a word outside every tracked shared mapping — heap, stack, and private mappings included — exactly like a private operation, so a program that mixes the flags on one word gets wakeups Linux would never deliver, and the robust owner-death wake, keyed the same flagless way, likewise reaches a private-flag waiter on such a word; a shared mapping whose backing Detcore could not resolve is tracked nowhere, so two processes sharing such a word instead miss each other's wakes.[^c36][^c27][^c40][^linux]
- G11 (unimplemented): when two argument errors coincide Detcore reports a different one than Linux, which copies and validates a timed command's timeout before its dispatcher refuses an unknown or realtime-flagged command and before its key admission refuses a misaligned word: a plain `FUTEX_WAIT` or `FUTEX_LOCK_PI` carrying the realtime flag with an unreadable or invalid timeout fails `EFAULT` or `EINVAL` on Linux but `ENOSYS` here, and a wait on a misaligned word with an unreadable timeout fails `EFAULT` on Linux but `EINVAL` here; each error alone matches Linux.[^c42][^c3][^c13][^linux]
- G12 (unimplemented): a signal ends a parked plain or PI wait with its restart form only where the backend declares it can interrupt a blocked wait, handing the kernel's signal delivery a restart errno to turn into `EINTR` or a restart, or under the in-guest delivery gate; elsewhere the wait parks with no signal watch, so a caught signal does not end it and it ends only at a modeled wake or its deadline, with that outcome's normal result, where Linux ends it at once. The signal exits in G2, G5, and G9 likewise hold only under that condition.[^c46][^c14][^linux]
