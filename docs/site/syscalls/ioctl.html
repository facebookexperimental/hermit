ioctl (16)

Strategy: determinized · dispatch: typed · discussion (new)

Facts as of 403e350e9e82 · prose checked 2026-11-20 at 403e350e9e82

In short

Natively, ioctl asks the driver behind a descriptor to answer a command word that nothing interprets in general, so the answer, its timing, and its side effects belong to the host kernel and the host device. On every path that enters the Detcore tool, Hermit determinizes the call as a whole while leaving most command words to whoever executes the forwarded call, which is the host kernel except on KVM, where the backend's Linux provider answers only a small named set and refuses the rest, and it answers a small named set itself, screens a few more before forwarding, and refuses a handful outright. The DBT copied child never enters that tool and is scoped separately below, while descriptors Detcore itself renders are answered from its own model except for the named fall-through words. Known gaps: 19.

Determinism strategy

What is nondeterministic natively. ioctl dispatches on a descriptor, a command word, and one argument whose meaning the command word alone decides: the kernel first answers a small generic set itself and hands everything else to the file or driver behind the descriptor, which may read or write guest memory, change device state, wait for another process, or fail with a driver-chosen error.[linux] Almost every observable can therefore move with host state: the return value and any output bytes, the error, whether the call waits at all, and what later calls on the same descriptor observe, including timestamps taken from the host clock and state belonging to another process.[linux] A socket timestamp query, an interface query, and a binder transaction all draw on different host sources behind the same entry point, so no single native answer is a function of the guest alone.[linux]

What Hermit does. On every execution that enters the Detcore tool, Detcore determinizes ioctl by keeping one shared typed dispatch and deciding per command word inside it: the classification lists the call among the determinized syscalls, the dispatch peels off the socket timestamp words to their own handler, and every other word reaches one main handler, with the call always observed even where an optimisation would otherwise pass calls through.[c1][c2][c3] Three interceptors run before that dispatch and can answer or refuse the call before any handler sees it: in a process whose alarm disposition is a guest handler on the route that virtualizes that signal, signal phase one refuses every ioctl with EOPNOTSUPP; under the network-trace modes (--record-networking and --replay-networking) the trace owner takes the interface, signal-driven, and recorded-channel words described below and ends the run before the typed dispatch; and the rendered-descriptor answers, with the adoption of received placeholders, answer their own named sets from the model and refuse the rest, also before the dispatch.[c34][c35][c22][c23] That handler refuses before it forwards anything else: a tick-setting command on a modelled timer descriptor ends the run where virtual time is modelled, because a host tick count must never disagree with the virtual expiration count, and that gate needs virtual time with sequentialized threads outside record and replay where the descriptor model is the one shared copy, which holds on the ptrace path, its e9patch preprocessing, KVM, DBT, and LiteInst-in-guest, while on SaBRe no model is shared and the timer descriptor itself is refused at creation, so this gate is unreachable there (G12).[c4][c28][c32] The remaining named interceptions, the screens, the binder router, and the rendered-descriptor answers below are the checked surface on tool-entering paths; every other command word is forwarded under the record and replay wrapper with no per-command handling on the host-kernel backends, and on KVM it is forwarded to the backend's Linux provider instead, which the gaps name family by family rather than claim as a host answer.[c18] Refusals inside the tool have a fixed order after the pre-dispatch interceptors: the timer tick refusal first, then the in-guest producer-arming refusal, then the owner screen (EFAULT for an unreadable owner, then EPERM for an owner naming one of Hermit's tasks), then the Ethernet ENODEV, then the nonblocking argument read (EFAULT), then the strict binder run-ending refusal before any binder argument is read, then the exit-report valve, then the binder waiting-effect refusals, then, outside record and replay, the shared-task refusal (a waiting call beside another task or a served debugger, refused without being issued: the run ends when it is fail-closed, and otherwise the call fails with EOPNOTSUPP), then the faulted-read and unnamable-descriptor refusals after the call, which likewise apply only outside record and replay, with rendered and timestamp answers in their own order and a forwarded word's own executor error last.[c4][c21][c5][c6][c13][c36]

The descriptor-generic interceptions are few and exact. An Ethernet tool command is refused with ENODEV for every descriptor before any forwarding, because host link state can change between runs; the close-on-exec pair update Detcore's own descriptor model, including a descriptor it lists without modelling, and the call itself still runs, so the modelled flag is what an exec observes; and a nonblocking command first reads its flag word, failing with EFAULT when that word cannot be read, before the split described under interface fidelity decides whether anything is forwarded.[c6][c9] The socket timestamp words never reach that handler at all: with time virtualized they are answered from the stored logical time of the last successful receive on that descriptor, and without it they are forwarded under the wrapper in their re-spelled form, except on KVM, where the re-spelled words meet the provider default stated below.[c10][c11] Binder words are the largest enumerated class: membership is decided on the masked command word alone, the descriptor is not consulted for membership, and two words the driver itself answers like any unknown request are deliberately left outside the set, so the same words on another driver keep their own meaning.[c12] What a binder call then does depends on whether it waits, which only its snapshot can say, since only the write-read and freeze arguments are ever read, once, after the exit-report barrier.[c14][c15]

Binder divergences are exact and are stated as behaviour, not smoothed into the forwarding umbrella. Under the strict binder policy every word in the binder set ends the run with the policy-refusal exit before its argument is read, but only on a descriptor not proven to be a different device; a descriptor proven to name another driver falls through, and fresh runs and replays are refused alike because reply payloads are not recorded.[c13][c16] Where a backend cannot name guest descriptors as host descriptors (KVM), identity is always unknown, so strict admission instead requires the host to offer binder no way in, and the request-word refusal remains the backstop.[c17][c33] Outside strict runs the routing is fixed: a call that does not wait runs in the caller's turn; a read-only call that waits runs off the turn only while its caller is the run's one task and no debugger is served, and otherwise it is refused without being issued, ending the run when it is fail-closed and otherwise returning EOPNOTSUPP to the guest; outside record and replay, a waiting call with a write half, or a freeze, is always refused in that same form, ending the run when it is fail-closed and otherwise returning EOPNOTSUPP to the guest without issuing the call.[c15][c36] Under record and replay every binder call is issued in the caller's turn before any routing, so the shared-task, waiting-effect, faulted-read and unnamable-descriptor refusals do not apply there; only the strict refusal and the exit-report valve do.[c18][c36] Outside record and replay both admission gates refuse on their boundary, so no waiting call with another task, a debugger, a write half, or a freeze ever runs off the turn beside another task.[c36] Before any admitted call reads its memory, a retired thread whose exit report is still missing past the sixty-second valve ends a fail-closed run with the named missing-report refusal and otherwise fails the call with EOPNOTSUPP without issuing it, and that valve is part of the ordered refusals above.[c36] Descriptors a read delivers are taken from the commands the call wrote only where the run records received descriptors: where the tool shares the guest descriptor table the backend discovers them itself and Detcore parses nothing, and without sequentialized threads nothing is recorded; a read half that failed with EFAULT while its read size was nonzero ends the run in a fail-closed run that records receipts instead of guessing what arrived, and a read whose delivered descriptors cannot be named in such a run is likewise refused by ending the run rather than leaving the guest a number Linux would never give it.[c19][c29][c36]

On KVM the forwarded call is executed by the backend's Linux provider rather than issued by Detcore against a host descriptor; Detcore's own code treats guest descriptors there as not host descriptors the tool can name. The provider's word set is text evidence from reverie-linuxemu/src/executor/ioctl.rs and reverie-linuxemu/src/executor/dispatch.rs, reached from reverie-kvm/src/runtime.rs, as the check cannot hash-cite outside detcore/: it answers only the readable-bytes word for inotify and FIFO descriptors, the nonblocking and close-on-exec words, and the Ethernet word with ENODEV, and it re-issues TCGETS, TIOCGWINSZ and TIOCGPGRP on the host descriptor, applies FIONBIO to that descriptor, and answers an inotify descriptor's FIONREAD from it, while every other word gets ENOTTY from the provider itself.[c17][c33] That default reaches the binder words, the owner and async words, the controlling-terminal words beyond the re-issued set, the re-spelled timestamp words when time is not virtualized, the tick word when its gate does not hold, and the extent and clone words on real files, together with the interface, block-device, and private-driver words, as gaps G1 through G5, G7, and G13 state.[c17][c33]

Two screens run before forwarding and change nothing they admit. An owner-setting word has its owner read on the ordinary route and read a second time on the in-guest route by the earlier producer check, is refused when that owner names one of Hermit's own tasks, and reaches the executor as Detcore's scratch-stack copy, so another guest thread rewriting the argument between the check and the executor read cannot change the owner the executor sees; an unreadable owner fails with EFAULT at the same read.[c5][c31][c21] A producer-arming check runs earlier still, only on the default in-guest route that covers both LiteInst and the in-guest trap, while the in-guest loader route leaves it off, which refuses host-timed producers (DBT does not, and the ptrace path, its e9patch preprocessing, KVM, and SaBRe forward instead): an async word turning asynchronous delivery on, or an owner word naming a nonzero owner, that would complete a host-timed signal producer is refused with EPERM, while an unreadable argument is left to the executor, which arms nothing.[c21] Separately, the words that let the host signal the guest at a host-chosen moment are recognised as a set, and where the backend's host-timed signals are physical (the ptrace path and its e9patch preprocessing) those signals are recorded for the whole container before the call runs; on KVM, DBT, SaBRe, and LiteInst-in-guest, whose host-timed signals are not physical, nothing is recorded; the call itself is then forwarded untouched on every tool-entering path, subject on KVM to the provider default above.[c20][c30] Descriptors Detcore itself renders are answered before the generic handling: a placeholder directory and a rendered file each answer their own named sets from the model and refuse the rest, as interface fidelity states, except that the close-on-exec pair, and on a rendered file also the async and nonblocking words, fall through to the generic handling, the rendered file's readable-bytes query falls through to the executor where the tool shares the guest descriptor table (DBT and SaBRe) and is answered from Detcore's shared cursor elsewhere, and Detcore's own inotify bookkeeping issues a readable-bytes query itself as an injected call that reaches the executor answer a guest query would get.[c22][c23][c24]

There is no second Detcore implementation of this call behind any instrumented backend switch. The same dispatch, handler, screens, and router run as the one shared Detcore tool on the ptrace path, its e9patch preprocessing, KVM, DBT-instrumented-root, SaBRe, and LiteInst-in-guest, and guest-visible answers change with each of these named conditions rather than in only two places: whether the tool shares the guest descriptor table (DBT and SaBRe), whether guest descriptors can be named as host descriptors (everywhere except KVM), which provider executes forwarded calls (the host kernel, or the KVM Linux provider with its ENOTTY default), whether host-timed signals are physical (the ptrace path and its e9patch preprocessing only), whether the default in-guest route refuses host-timed producers (LiteInst and the in-guest trap on that route only; DBT does not, and the loader route leaves it off), whether the timer model is shared (everywhere except SaBRe), whether time is virtualized, whether threads are sequentialized, whether the run is in record or replay modes, whether the run serves a debugger, whether the network-trace modes (--record-networking and --replay-networking) own the call, whether the process virtualizes its alarm signal and handles it, and the strict-binder and fail-closed switches.[c2][c17][c19][c28][c32][c33][c34][c35] Among those, the rendered-file readable-bytes query is forwarded where the tool shares the guest table (DBT and SaBRe) and answered from Detcore's shared cursor elsewhere, descriptor receipts are discovered where the table is shared, recorded where it is not and threads are sequentialized, and unrecorded otherwise, the producer refusal answers EPERM only on its route, a binder word on KVM under the strict policy ends the run on any descriptor because identity is always unknown there while a descriptor known not to be binder falls through elsewhere, and the virtualized timestamp answer replaces the executor answer whenever time is virtualized.[c23][c19][c21][c17][c10] The DBT copied child is the one execution that never enters that tool: in a fail-closed run (the default, and always under the strict switch) every ioctl there ends the run except a foreground-group query, which is emulated as ENOTTY, and in a run with the unsupported-calls opt-in every ioctl there runs natively with no Detcore handling at all (G11), where the copied-child branch itself is text evidence from inguest-engine/src/native/copied_action.rs with inguest-engine/src/native/bootstrap.rs, as the check cannot hash-cite outside detcore/, the Detcore premise cited here being the shared dispatch it bypasses.[c2] Any stronger sameness claim across configurations would need a run, not this code reading, and this page makes none.[c2]

Interface fidelity. Honored, coalesced, and rejected behaviour differs per word, and the list below is the checked per-command coverage: each entry names the guest-visible result Detcore guarantees, and forwarding means the executor's own result, output, and error for that word, issued whole so the executor's partial-completion and restart behaviour is preserved rather than remodelled, where the executor is the host kernel except on KVM, where it is the backend's Linux provider with the default stated above.[c18][c20][linux]

  • SIOCETHTOOL is rejected with ENODEV on every descriptor, before forwarding.[c6]
  • FIOCLEX and FIONCLEX have their modelled close-on-exec flag updated, then are forwarded, including on a descriptor Detcore lists without modelling.[c9]
  • FIONBIO is answered directly on the split below where it applies, and otherwise forwarded and then modelled.[c7][c8]
  • TFD_IOC_SET_TICKS on a modelled timer descriptor gets the run-ending refusal where the timer gate holds.[c4]
  • SIOCGSTAMP and its new spelling give the stored logical receive time as a timeval where time is virtualized, and otherwise are forwarded re-spelled subject to the KVM provider default.[c10][c11]
  • SIOCGSTAMPNS and its new spelling give the stored logical receive time as a timespec where time is virtualized, and otherwise are forwarded re-spelled subject to the KVM provider default.[c10][c11]
  • The binder set is routed by waiting behaviour, with strict runs refused as stated above.[c13][c15]
  • FIOSETOWN and SIOCSPGRP are owner-screened and copied, producer-screened where that route applies, and signal-recorded where host-timed signals are physical, then forwarded subject to the KVM provider default.[c5][c21][c20]
  • FIOASYNC is producer-screened where that route applies and signal-recorded where host-timed signals are physical, then forwarded subject to the KVM provider default.[c21][c20]
  • TIOCSCTTY, TIOCSPGRP, and a qualifying TIOCGPTPEER get signal recording only, then are forwarded untouched subject to the KVM provider default.[c20]
  • Every other word on an ordinary descriptor is forwarded unchanged under the record and replay wrapper on the host-kernel backends, and on KVM meets the provider word set and its ENOTTY default instead.[c18][c17]

The nonblocking split is the one place the same word has two guest-visible paths. Where the descriptor predicate holds and the descriptor is already physically nonblocking, the call sets only the logical flag, publishes pipe status where that publication applies, and returns success without forwarding, so clearing the guest-visible flag can never clear the physical flag the scheduler's retry discipline depends on; everywhere else the call is forwarded and the resulting logical flag is then recorded in the descriptor model.[c7][c8][c9] The predicate itself needs sequentialized threads with the external-socket debug spelling off, excludes a descriptor with an inherited external reader, and is mode-dependent: outside record and replay it covers pipes, internal sockets, and the socket, event, and inotify kinds as the code lists them, while inside record and replay only an already physically nonblocking pipe or internal socket qualifies, which is why a single-path claim for this word would be wrong in one mode or the other, and pipe-status publication itself needs the alarm-virtualizing backend with sequentialized threads.[c8][c37] On a descriptor Detcore lists without modelling, the same word fails with EBADF from Detcore before anything is forwarded, because such descriptors are received anonymous inodes and receipts whose facts could not be taken and are never in the modelled table, where the executor would have answered the call, and the virtualized timestamp path fails the same way on such a descriptor (G19).[c37][c10] Timestamp fidelity turns on an encoding fact the page must not blur: the legacy words carry no direction or size bits, so nothing downstream can identify their output, and only the re-spelled words, whose layout encodes the output size, are ever what gets recorded; on the virtualized path a descriptor that is not a socket fails with ENOTTY, a socket with no stored receive time fails with ENOENT, and an unusable output address fails with EFAULT, in that order.[c10][c11] With time virtualized that answer diverges for socket families that have no timestamps, such as the unix family: Linux answers ENOTTY where the family offers no timestamp operation, while Detcore treats every socket kind the same and answers ENOENT or the stored logical receive time that every socket receive records, so such a socket gets a timestamp or ENOENT where Linux gives ENOTTY (G16).[c10][linux] On rendered descriptors the error order is likewise the answer, and the two kinds differ: the placeholder directory emulates the nonblocking flag on its modelled status, answers an asynchronous change it cannot honour with ENOTTY while a no-change request succeeds, reports its fixed block size and a zero size answer, gates freeze and thaw behind the administrative capability before refusing them with EOPNOTSUPP or EINVAL, refuses an extent query outright with EOPNOTSUPP, answers cloning by reading any range argument first and then judging the source descriptor, answers dedup with EFAULT, then ENOMEM, then EINVAL, then EISDIR, answers flag-setting by reading its argument with EFAULT and then ENOTTY, and refuses every unlisted word as ENOTTY; the rendered file answers its extent query with EOPNOTSUPP, judges cloning from its source, sends the descriptor-generic words back to the generic handling, refuses the rest as ENOTTY, and answers the block-mapping and freeze and thaw words with EPERM and no capability check at all, where Linux would answer a capable caller with EOPNOTSUPP or EINVAL and the block-mapping word in particular wants the raw-I/O capability and answers EINVAL.[c22][c23][linux] Those two ENOTTY defaults belong to rendered descriptors alone: Detcore has no general unknown-command refusal, and an unlisted word on an ordinary descriptor receives the executor's answer, including the executor's own not-a-terminal error where the driver gives one, which on KVM is the provider's ENOTTY for every unlisted word rather than a driver answer.[c18][linux] Refusals by command class, in the order the handler reaches them after the pre-dispatch gates, are: signal phase one refuses every word with EOPNOTSUPP on its route; the network-trace modes end the run for their words with the policy-refusal exit; timer tick words end the run where the timer gate holds; producer-arming async and owner words fail with EPERM on the default in-guest route only; owner words fail with EFAULT for an unreadable owner before EPERM for an owner naming one of Hermit's tasks; the Ethernet word fails with ENODEV; the nonblocking word fails with EFAULT for an unreadable flag word and with EBADF on an unmodelled descriptor; binder words under the strict policy end the run before the argument is read, the missing exit report ends a fail-closed run or fails with EOPNOTSUPP, outside record and replay binder waiting-effect words are always refused, ending the run when fail-closed and otherwise failing with EOPNOTSUPP without being issued, outside record and replay a waiting call beside another task or a served debugger is refused in the same form without being issued, and, also outside record and replay, the faulted-read and unnamable-descriptor refusals end a fail-closed run that records receipts; rendered-descriptor words fail with their modelled errors in modelled order as above; timestamp words under virtualized time fail with ENOTTY, then ENOENT, then EFAULT; every other word fails only with the executor's own error, which on KVM is the provider's ENOTTY for unlisted words.[c34][c35][c4][c21][c5][c6][c13][c36][c22][c23][c11] Every non-binder word runs in the caller's turn, so a forwarded word that waits in the executor therefore holds the turn and, with sequentialized threads (the default), stalls every other guest thread, as a terminal drain waiting for a peer to read does, and Detcore adds no interruption or restart path of its own to a forwarded word (G17).[c15][c18] A descriptor Detcore cannot find at all fails as the forwarded call or the screen reading it fails, never as an invented success, while the unmodelled-descriptor EBADF above is Detcore's own answer before forwarding.[c5][c37]

Record & replay. The call is subscribed in both run and record/replay modes (code facts in the Appendix).[c2] The subscription means the forwarding wrapper records in the recording phase and substitutes the recorded answer in replay for the words it can represent, where the Detcore premise cited here is the in-turn forwarding through that wrapper and the recorder, replayer, and decoder behaviour itself is text evidence from hermit-record/src/recorder/fs.rs, hermit-replay/src/replayer/fs.rs and reverie-syscalls/src/args/ioctl.rs, as the check cannot hash-cite outside detcore/: a word whose output the decoder can size records its output bytes, the close-on-exec and nonblocking words record only their return value, a clone word records a snapshot of the destination that replay materialises into its own root, and a word whose output the decoder cannot size, whether behind a nested pointer or direct with no direction and size bits to size it, records only its return value so replay returns that value with the guest buffer untouched and whatever the guest later reads is stale memory, with no refusal (G8; the typed words below panic instead).[c18] The decoder sizes nine typed words (TCGETS, TCSETS, TIOCGWINSZ, TIOCSWINSZ, TIOCGPGRP, TIOCSPGRP, FIONREAD, SIOCGIFINDEX and SIOCETHTOOL), the recorder and replayer handle five more before the decoder (FICLONE, FICLONERANGE, FIOCLEX, FIONCLEX and FIONBIO), and SIOCGSTAMP is re-spelled before it is recorded, so it is sized as its new spelling; every other typed word, forty of the fifty-five typed words, panics instead of recording or replaying at all: on record a successful call panics when its output is read, and on replay every such call panics when its direction is asked, whether the recorded call succeeded or failed. The forty are FIOSETOWN, SIOCSPGRP, FIOGETOWN, SIOCGPGRP, SIOCATMARK, FIOASYNC, TIOCSCTTY, TIOCGPTPEER, TCSETSW, TCSETSF, TCGETA, TCSETA, TCSETAW, TCSETAF, TCSBRK, TCXONC, TCFLSH, TIOCEXCL, TIOCNXCL, TIOCOUTQ, TIOCSTI, TIOCMGET, TIOCMBIS, TIOCMBIC, TIOCMSET, TIOCGSOFTCAR, TIOCSSOFTCAR, TIOCLINUX, TIOCCONS, TIOCPKT, TIOCNOTTY, TIOCSETD, TIOCGETD, TCSBRKP, TIOCSERCONFIG, TIOCSERGWILD, TIOCSERSWILD, TIOCGLCKTRMIOS, TIOCSLCKTRMIOS and TIOCSERGETLSR (G14).[c18] Two exact exceptions complete the picture. The emulated nonblocking path returns before the wrapper in both phases, so it is never recorded and both phases evolve the logical flag from Detcore bookkeeping alone; the forwarded form, by contrast, goes through the wrapper like any other forwarded word.[c7][c8] And the legacy timestamp words are recordable only through their re-spelled forms: the legacy spelling itself is never what the recording holds, so claiming the legacy query is recorded as spelled would overclaim the wrapper.[c11] Binder is the named limitation of this mode: every binder call is forced into the caller's turn through the wrapper and neither the nested command buffer nor installed descriptors are restored, so binder is unsupported under record and replay rather than approximately replayed.[c18] The Ethernet tool word is refused identically in both phases, once by the handler for its host-state reason and once by the recording layer because its nested output cannot be represented, where that second refusal is special-cased for that word alone rather than being the only word whose loss would change guest memory; the two refusals share an error and nothing else.[c6] Under the network-trace modes the interface and route words on any descriptor, the async and owner words on an internet socket, and every word on a recorded channel socket end the run with the policy-refusal exit before Detcore's handler runs, rather than being treated as ordinary forwarding, and those same modes are the conditions list above (G18).[c35] Reserved-input classification sees this call only narrowly: a handful of descriptor-installing words mark the call as able to install descriptors, an ioctl on a userfault descriptor or one whose argument overlaps reserved input exposes the unknown-driver boundary, and unrelated words are explicitly not tainted, so a native error from such a call is never treated as proof that nothing was installed.[c25][c26]

Known gaps

  • G1 (unimplemented; ptrace, e9patch-preprocessed ptrace, KVM, DBT-instrumented-root, SaBRe, LiteInst-in-guest): terminal control words beyond the signal-recording set are forwarded with no model, so on the host-kernel backends their host timing, output, and session effects reach the guest as the host produces them, while on KVM the provider answers only its re-issued terminal words and refuses the rest with ENOTTY, and a guest depending on terminal state repeating has no fallback inside this call. On the DBT copied child the same words end the run in a fail-closed run and run natively in a run with the unsupported-calls opt-in (G11).[c20][c18]
  • G2 (unimplemented; ptrace, e9patch-preprocessed ptrace, KVM, DBT-instrumented-root, SaBRe, LiteInst-in-guest): interface and routing words other than the refused Ethernet tool word are forwarded into the caller's network namespace on the host-kernel backends, so addresses, flags, and routes are host facts that differ between hosts and between a recording and its replay, while on KVM those words get the provider's ENOTTY instead of any namespace answer, and under the network-trace modes they end the run as G18 states. On the DBT copied child the same words end the run in a fail-closed run and run natively in a run with the unsupported-calls opt-in (G11).[c27][c35][c18]
  • G3 (unimplemented; ptrace, e9patch-preprocessed ptrace, KVM, DBT-instrumented-root, SaBRe, LiteInst-in-guest): block-device words and private driver words are forwarded unenumerated on the host-kernel backends, so any device state, timing, or output behind them is host behaviour, while on KVM they get the provider's ENOTTY instead, and there is no fallback inside this call for a guest that needs those answers to repeat. On the DBT copied child the same words end the run in a fail-closed run and run natively in a run with the unsupported-calls opt-in (G11).[c18]
  • G4 (unimplemented; ptrace, e9patch-preprocessed ptrace, KVM, DBT-instrumented-root, SaBRe, LiteInst-in-guest): filesystem-generic words on ordinary files are forwarded unenumerated on the host-kernel backends, and in particular an extent-mapping query on a real file returns the host filesystem's extent layout there, while on KVM the extent and clone words on real files get the provider's ENOTTY instead, and the refusal that closes this on rendered descriptors does not extend to real files on any backend. On the DBT copied child the same words end the run in a fail-closed run and run natively in a run with the unsupported-calls opt-in (G11).[c18][c23]
  • G5 (unimplemented; ptrace, e9patch-preprocessed ptrace, KVM, DBT-instrumented-root, SaBRe, LiteInst-in-guest): binder payloads are not determinized outside a strict run: what a binder call returns and when it returns are another process's input, and only the strict refusal removes the dependence, by ending the run; on KVM a strict run is admitted only where the host offers binder no way in, the provider otherwise answers binder words with ENOTTY, and on the DBT copied child a fail-closed run ends before any payload and a run with the unsupported-calls opt-in takes the payload natively with no reporting (G11).[c13][c15]
  • G6 (unimplemented; ptrace record and replay): binder under record and replay restores neither the nested command buffer nor descriptors a read installed, so a guest using binder there is unsupported rather than replayed approximately; the guest must run without the strict binder policy and outside record and replay, or without binder, since the strict policy refuses binder in fresh runs and replays alike.[c18]
  • G7 (by design; ptrace, e9patch-preprocessed ptrace, KVM, DBT-instrumented-root, SaBRe, LiteInst-in-guest): timestamp queries with time unvirtualized are forwarded to the host clock through the re-spelled words on the host-kernel backends, so the returned receive time is a host reading there, while on KVM the re-spelled words get the provider's ENOTTY and no host reading at all; virtualized time is the configuration that makes this answer repeat. On the DBT copied child the same queries end the run in a fail-closed run and read the host clock natively, without the wrapper, in a run with the unsupported-calls opt-in (G11).[c11]
  • G8 (unimplemented; ptrace record and replay): every word whose output the recording decoder cannot size, other than the typed words that panic instead (G14), whether its output hides behind a nested pointer or is direct with no direction and size bits to size it, as most legacy interface words are, records only its return value, so replay returns that value with the guest buffer untouched and any output the guest later reads is whatever its memory already held, with no refusal; the Ethernet word is refused only because it is special-cased, not because it is the only such word.[c18][c6]
  • G9 (unmeasured; ptrace, e9patch-preprocessed ptrace, KVM, DBT-instrumented-root, SaBRe, LiteInst-in-guest): named guest evidence covers only the close-on-exec and nonblocking round trips, the readable-bytes parity contract, the Ethernet refusal, the timestamp queries, binder descriptor passing, and the producer probe; the remaining named words in the coverage list, the routed binder words beyond descriptor passing, and the timer tick refusal have no per-command guest test named in the Appendix, so their prose rests on the cited code alone.[c18]
  • G10 (unimplemented; ptrace, e9patch-preprocessed ptrace, KVM, DBT-instrumented-root, SaBRe, LiteInst-in-guest): reserved-input coverage stops at the direct argument: effects of an unknown driver reached through nested pointers, and any descriptor an unlisted word installs without naming it, remain outside that classification's scope, and no error from such a call proves their absence. On the DBT copied child no Detcore classification runs at all (G11).[c25][c26]
