# Hermit Error Catalog

This catalog maps Hermit's actionable errors and warnings to their likely cause
and a concrete next step. Match the stable text shown in **Message**; values such
as paths, thread IDs, and syscall arguments vary between runs.

Hermit prints an error chain as `Error: ...` followed by indented `> ...`
causes. Diagnose the last OS error in that chain first. A guest program's own
nonzero exit or `errno` is not necessarily a Hermit failure.

The **Class** column uses these labels:

- **Configuration**: change the command, input, permissions, or host policy.
- **Unsupported**: the guest uses behavior Hermit does not determinize.
- **Internal bug**: an invariant failed; flags may help isolate the problem but
  cannot fix it.

Diagnostic modes trade away guarantees. `--namespace-only` disables
interception (except a seccomp filter on `kill`) and determinization.
`--strace-only` keeps interception for logging but disables virtual inputs,
deterministic I/O, RCB time, and serialized scheduling. Options beginning with
`--no-` similarly weaken reproducibility.

## Startup And Configuration

| Message | Class | Trigger | Fix |
| --- | --- | --- | --- |
| `HERMIT_CHOSEN_JSON_INPUT_PROVENANCE` | Unsupported | A Chosen schedule or priority replay lacks recognized reserved-input provenance, or its ABI/address/page extent differs. Refused before guest startup with status 122. This includes every pre-facility Chosen JSON file; editing or a caller override does not qualify it. | Record the run again with this Hermit, or replay the original with its producing Hermit. See [Chosen IDs](CHOSEN_IDS.md). |
| `HERMIT_CHOSEN_BINARY_INPUT_PROVENANCE` | Unsupported | The actual inner Tool records/replays binary events (or has an unknown stream role), or Config selects binary mode, while Chosen IDs are requested. Binary streams have no reserved-input provenance. Refused before target startup with status 122, including a new recording. | Use Namespace IDs for binary record/replay, or plain Chosen with qualified schedule JSON. Config flags or a JSON side file cannot override the typed stream. |
| `unexpected argument`, `invalid value`, `required arguments ... not provided`, or `unrecognized subcommand` | Configuration | Clap rejected the command line before Hermit started. | Run `hermit --help` or `hermit <subcommand> --help`. Put `--` before `PROGRAM` when guest arguments begin with `-`. |
| `unable to parse name=value from '...'` or `unable to parse env var name or name=value from '...'` | Configuration | `--env`/`-e` was not `NAME` or `NAME=VALUE`, or used an invalid variable name. | Use `-e NAME` to pass through a host value or `-e NAME=VALUE` to set one. |
| `Attempt to pass through env var ..., but it is not set in host environment` | Configuration | `-e NAME` named a variable absent from Hermit's environment. | Export it first, use `-e NAME=VALUE`, or remove the option. |
| `--no-virtualize-time also requires --no-virtualize-metadata` | Configuration | Host time was requested while deterministic metadata remained enabled. | Add `--no-virtualize-metadata`, or remove `--no-virtualize-time`. The former weakens determinism. |
| `--sched-sticky-random-param must be between 0 and 1 inclusive` | Configuration | The sticky scheduler probability was outside its valid range. | Pass a value from `0` through `1`. |
| `Cannot set both --replay-preemptions-from and --replay-schedule-from` | Configuration | Two mutually exclusive replay sources were supplied. | Keep exactly one replay option. |
| `unable to parse <thread_id>:<logical_time> from '...'` | Configuration | A thread/time option did not contain two valid integers separated by `:`. | Use `THREAD_ID:LOGICAL_TIME`, with both fields expressed as unsigned decimal integers. |
| `Unable to parse string as exit code constraint` or `Exit code constraint ... is out of range` | Configuration | Analyze or bisect received an invalid `--target-exit-code`. | Use an exit code from 0 to 255 (128 plus the signal number for a signal death), `nonzero`, `none`, or `any`. |
| `Program ... does not exist or is not accessible` | Configuration | The executable path is absent in the guest view, including the isolated `/tmp`. | Correct the path/mount. For a host `/tmp` binary, use `--bind=SOURCE:TARGET` or, diagnostically, `--tmp=/tmp`. |
| `Program ... is a directory` | Configuration | `PROGRAM` resolved to a directory. | Select the executable file. |
| `Program ... is not a regular executable file` | Configuration | `PROGRAM` is a device, socket, FIFO, or other non-regular file. | Use a regular executable or a supported interpreter invocation. |
| `Program ... is not executable` | Configuration | Execute permission is missing. | Run `chmod +x PROGRAM` or invoke its interpreter explicitly. |
| `Program ... has an empty shebang interpreter` | Configuration | A script begins with `#!` but contains no interpreter. | Correct the script's first line. |
| `uses shebang interpreter ..., but the interpreter does not exist` | Configuration | The script interpreter is absent in the guest filesystem. | Install, mount, or correct the interpreter path. |
| `uses shebang interpreter ..., but it is not an executable file` | Configuration | The shebang target exists but cannot be executed. | Fix its type/permissions or select another interpreter. |
| `Could not resolve program ... in guest PATH` | Configuration | A bare program name was not found using the guest environment. | Pass an absolute path, set `PATH`, or use `--base-env=host`. |
| `--bind source ... does not exist` or `--mount source ... does not exist` | Configuration | A requested host mount source is absent. | Create/correct the source before starting Hermit. |
| `--bind target ... is outside guest /tmp and the guest's private /dev/shm, so this option has no effect` | Configuration | `--bind` was used for a target it cannot expose. | Use Docker-style `--mount` for targets outside `/tmp` and `/dev/shm`. |
| `cannot bind ... from host /dev/shm to ... in the guest's private /dev/shm` | Configuration | A `--bind` or `--mount` below `/dev/shm` names a source in the host's `/dev/shm`, which the guest's private `/dev/shm` covers before the bind is made. | Pass `--bind /dev/shm` to keep the host's `/dev/shm`, or bind the source elsewhere (for example below `/tmp`). |
| `cannot bind ... from host /tmp to ... in the guest's private /dev/shm` | Configuration | `TMPDIR` or `--tmp` keeps the guest's private `/tmp` in the host's `/dev/shm`, so the private `/tmp` is bound first and covers host `/tmp` before a bind into `/dev/shm` from there is made. | Bind the source from outside `/tmp`, or keep the private `/tmp` outside `/dev/shm`. |
| `--bind target ... is below a guest /dev/shm that is not Hermit's private one` | Configuration | A `--bind` below `/dev/shm` in a run where a `--mount` or `--bind` at `/dev/shm` replaced the private one, or `--bind /dev/shm` kept the host's. | Use `--mount type=bind,...` to mount into the replacement. |
| `Program ... is under host /dev/shm, but Hermit gives the guest a private /dev/shm` | Configuration | The guest program is in the host's `/dev/shm`, which the guest cannot see. | Move the program, or pass `--bind /dev/shm`. |
| `cannot mount at ...: the guest's /dev/mqueue is its own mqueue filesystem` | Configuration | A `--mount` below `/dev/mqueue`, which the guest's own mqueue mount would cover. | Mount at `/dev/mqueue` itself to replace the private mount. |
| `Failed to create temporary log files` | Configuration | `--verify` could not create its temporary artifacts. | Check `TMPDIR`, directory permissions, free space, and file-descriptor limits. |
| `Failed to open log file` | Configuration | The requested log path cannot be created. | Make the parent directory writable, remove a conflicting directory, and check disk space. |
| `Failed to fork capability probe` or `Failed to wait for capability probe` | Configuration | Hermit's ptrace/seccomp startup probe could not fork or reap its child. | Check process limits and container policy; retry `--namespace-only` to isolate interception from namespace setup. |
| `Hermit cannot use ptrace` / `PTRACE_TRACEME probe was denied` | Configuration | Container seccomp or the host Yama/LSM policy denied parent-child ptrace. | Permit same-UID parent-child ptrace. Use `--namespace-only` only as a smoke test; it does not determinize. |
| `legacy clone exit-signal validation is unsupported or unproven` | Unsupported | The chosen-ID admission probe did not observe EFAULT for the valid-signal control and EINVAL for signal 65. Required IDs, including Chosen-record replay, are refused with status 122; an automatic selection instead warns and uses Host IDs. Both probe results are included. | Use a host that passes the probe. For a new run or recording, omit `--no-namespace` and `--pid-base` to use a PID namespace; an existing Chosen record still requires a compatible host. |
| `hermit inherited a seccomp filter (...) from whatever launched it`, exit 122 | Configuration | Hermit started under a seccomp filter it does not record: a container runtime's default profile, or a `hermit run --namespace-only` guest, which carries Hermit's filter on `kill` (https://github.com/rrnewton/hermit/issues/4065). | Run Hermit where no filter is inherited (for Docker, `--security-opt seccomp=unconfined`; not inside a `--namespace-only` guest), or pass `--unsafe-ignore-host-seccomp` to accept a run that may not reproduce. |
| `Hermit cannot install its tracee seccomp filter` | Configuration | The host denied seccomp or `prctl(PR_SET_NO_NEW_PRIVS)`. | Permit those operations in the container profile. `--namespace-only` installs a seccomp filter on `kill` too, so it fails the same way there. |
| `hermit could not install the --namespace-only kill filter in the guest: seccomp(...) failed with E...`, exit 122 | Configuration | The guest of a `--namespace-only` run could not install Hermit's seccomp filter on `kill` (https://github.com/rrnewton/hermit/issues/4065): a policy denies seccomp (EPERM, EACCES), the caller's seccomp filters already have a listener (EBUSY: another `--namespace-only` run, a seccomp-notify sandbox), or the kernel lacks `SECCOMP_FILTER_FLAG_NEW_LISTENER`. Hermit refuses rather than run the guest without the filter. | Run Hermit where seccomp is allowed and no other seccomp listener is installed. |
| namespace, mount, UID/GID-map, `EPERM`, or `Sandbox container exited unexpectedly` | Configuration | User/PID/mount namespaces are unavailable or their setup was denied. | Verify `unshare --user --map-root-user --pid --mount --fork true`; enable unprivileged namespaces and required mounts in host/container policy. |
| `Container exited unexpectedly` | Configuration | A record/analyze helper container died before returning its result. | Read the preceding cause/log. Check namespaces, mounts, executable visibility, and resource limits. |
| `First run during --verify exited with code ...` or `terminated by signal ...` | Configuration | The first verification execution on the generic runner returned a status rejected by `--verify-allow`, so no second run or comparison occurred. | Inspect the reported status and the preceding guest stdout/stderr. Fix the guest failure or select the intended `--verify-allow` policy before comparing determinism. |
| `kvm_address_space_limit: --backend=kvm refuses to start under a finite RLIMIT_AS (soft ..., hard ...)`, exit 122 | Configuration | Hermit ran the KVM backend under a finite soft address-space limit (`ulimit -v`, `prlimit --as`, a harness's `RLIMIT_AS`). reverie-kvm reserves 3 GiB of host address space for every guest process, plus 3 GiB for each exec in flight, and keeps an exited child's until its host thread releases it, so the peak follows the guest's process tree and host thread scheduling; under a finite limit a run would stop at a point those decide (https://github.com/rrnewton/reverie/issues/1225). Hermit does not raise the limit itself. The guest has not started. | Run Hermit with `ulimit -v unlimited` (raising a finite hard limit needs privilege) and bound its memory with a cgroup (`memory.max`). `memory.max` charges the memory the run uses (the pages guests touch, Hermit's own heap, page cache and kernel memory such as KVM's), not address space that is only reserved; a run that reaches it is killed by the kernel's OOM killer wherever it then is, not refused by name, so size the bound for the workload. |
| `KVM exec: host address space ran out: reserving N bytes of host address space for the guest memory that validates the new image failed (...)`, exit 122 | Configuration | On KVM, the host refused a resource an exec needs after a launch that passed the `RLIMIT_AS` check: the limit was lowered after launch, or another host limit such as `vm.max_map_count` or `RLIMIT_NOFILE` was reached. The same refusal has these other forms, each naming what ran out and the limit: `KVM exec: host memory ran out: allocating N bytes for ... failed` (the new program's image, a copy of `/proc/self/exe`, or a retained image); `KVM exec: host memory ran out: loading the new image into the validation memory failed (...)` (the loader's copy of the image, or its program interpreter); `KVM exec: host file descriptors ran out: ...` (EMFILE, naming `RLIMIT_NOFILE`) and `KVM exec: the host's file table ran out: ...` (ENFILE); `KVM exec: a host resource ran out: ...` (any other host error reserving the validation memory); and `KVM exec: host memory ran out: a host call or allocation preparing the new image failed with ENOMEM` (any other host ENOMEM). The exec ran none of the new image; the guest never sees the errno (with `--allow-unsupported-syscalls` it gets `ENOMEM`, after the same message). | Leave `RLIMIT_AS` unlimited for the whole run, and check the host limit the message names. |
| `KVM exec: host memory ran out after the old image was discarded: replacing the image failed (...)`, exit 122 | Configuration | On KVM, an exec passed its preflight and discarded the old image, and then the host refused a resource while the new image loaded: the limit was lowered, or the memory taken, between the preflight and this second load, or a KVM ioctl that sets up the new image failed with ENOMEM. `host file descriptors ran out` and `the host's file table ran out` are the same refusal for a descriptor. The old image cannot be restored, so the run ends here; the guest sees no errno. The second load opens the program interpreter and the working directory again by path: if one of them changed since the preflight, the run ends as an internal failure (exit 125) instead, or the new image starts with an interpreter the preflight did not check. | As above: keep the host's limits unchanged for the whole run. |
| `KVM guest execution failed: failed to allocate guest memory: ...`, or `memory allocation of N bytes failed` followed by `HERMIT_INTERNAL_FAILURE class=container-child-exit status=Signaled(SIGSEGV, true)`, exit 125 | Configuration | On KVM, a host limit was lowered after launch below what the run needs: the host refused a fork's guest memory (3 GiB), or an allocation of Hermit's own process that has no failure path failed. Such an allocation is either of a fixed size (for example 288 bytes) or one an exec bounds: its path, argv and envp, a `#!` line's arguments, the PT_INTERP path (4 KiB) and the program-header table (64 KiB, as Linux bounds it), as reverie-kvm's README lists. Both are still reported as internal failures (exit 125), not as named refusals. | Keep `RLIMIT_AS` unlimited for the whole run; bound memory with a cgroup instead. |
| `--max-timeslice requires user-space perf counters ... continuing with timer preemption disabled` | Configuration | `perf_event_open` was blocked by `perf_event_paranoid`, seccomp, or missing VM PMU exposure. | Enable user PMU access, or pass `--max-timeslice=disabled`. Disabling it can let CPU-bound threads run until another event. |
| `Hardware perf counters are not supported on this machine. Records/Replays may randomly fail` | Configuration | Record/replay metadata setup could not use the PMU and disabled preemption. | Enable user PMU access before recording and replay on equivalent hardware, or expect weaker schedule fidelity. |
| `WARNING: this host's retired-branch counter failed Reverie's performance-counter validation. ...` | Configuration | `hermit run`, `hermit analyze`, `hermit bisect` or `hermit record start` went on without `--strict` on a host whose retired-conditional-branch counter fails that validation (for example the AMD Zen SpecLockMap erratum, or counters a VM does not virtualize faithfully), in a run that times preemptions with the counter; `--strict` refuses the same command. The line names what is then not guaranteed for that command: the same arguments and seed, or a preemption record, reproducing a run; analyze and bisect trials agreeing, and what they report reproducing; or a replay following its recording. An `analyze` or `bisect` report repeats the line as `branch_counter_warning`. The text after `Reverie reports:` names the failed check and its counts, which vary from run to run. | Reproduce findings on a host whose counters pass the validation (`hermit host-capabilities` reports `exact-branch-counter: PRESENT` with the validation passed; a host without perf counters also reports PRESENT, but has no timer preemption at all), and use `--strict` there. Where the reason names a workaround (the SpecLockMap one), apply it and check `hermit host-capabilities` again. A `hermit run` with `--max-timeslice=disabled` does not time preemptions with the counter and does not warn, at the cost of all timer preemption; Reverie's own `PMU validation failed` log line still appears. |

## Injection Mechanisms

| Message | Class | Trigger | Fix |
| --- | --- | --- | --- |
| pselect6-wrapper-validation-unsupported: ... | Unsupported | A Guest implementation does not provide the closed Tool validation-injection contract. This is a mechanism failure, not a guest errno. | Implement and validate the purpose on that Guest; do not substitute EINVAL or ordinary injection silently. |
| `runtime-private smaps view unavailable: mixed ownership has unsupported per-VMA accounting` | Unsupported | One kernel VMA contains both guest and authenticated runtime-private bytes. Smaps reports aggregate VMA accounting, so the shared projector cannot faithfully assign it to guest fragments. No partial snapshot or guest errno is substituted. | Use Maps if mapping extents alone suffice; split Smaps accounting is unsupported. |
| `runtime-private smaps view unavailable: ...` | Unsupported | Opened-target ownership is unbound, retired or changed, capture is not sequentialized, or snapshot framing cannot be validated. | Preserve the named reason when reporting the failure. Hermit refuses to project using guessed ownership or ambiguous sections. |

| Message | Class | Trigger | Fix |
| --- | --- | --- | --- |
| `--imprecise timers with --replay-preemptions-from ... won't replay precisely` | Configuration | Approximate timers were enabled during precise preemption replay. | Remove `--imprecise-timers`. |
| `--stop-after-turn will have no effect if --no-sequentialize-threads is enabled` | Configuration | A scheduler stop condition was combined with no scheduler. | Remove `--no-sequentialize-threads` or the ineffective stop option. |
| `--stop-after-iter will have no effect if --no-sequentialize-threads is enabled` | Configuration | An iteration stop condition was combined with no scheduler. | Remove `--no-sequentialize-threads` or the ineffective stop option. |

| `manually set log lvl ... but need DEBUG for selfcheck/verbose functionality` | Configuration | Analyze self-checks need debug events that the chosen log level omits. | Put `--log=debug` before `analyze`. |
| `run without any --filter arguments, so accepting ALL runs` | Configuration | Analyze has no target predicate. | Add an exit, stdout, stderr, or other target filter. |
| `performing --search with system randomness` | Configuration | Analyze search has no reproducible seed. | Re-run with the printed `--analyze-seed=N`. |
| `WARNING: DESYNCs found` | Configuration | Verification found replay events that diverged. | Treat the recording, binary, filesystem, environment, and Hermit revision as one immutable set; inspect the desync details. |
| `WARNING: ... looks like a hardware emulator (VMM). Hermit's host-time virtualization exposes mutually inconsistent clock sources ...` | Configuration | A `qemu-system-*` program was launched with Hermit's virtual clock enabled, and its own command line does not already pass `-icount`. Its emulated guest derives TSC from a synthetic RDTSC but PIT/PM/APIC/RTC from virtualized `clock_gettime`, and those bases are not mutually coherent. | Two routes were measured to reach a booted guest: make QEMU use one instruction-derived clock via `-icount shift=0,sleep=off`, or pass `no_timer_check` on the nested guest's kernel command line. `-icount` forecloses multi-threaded TCG, which QEMU refuses to combine with it. `--no-virtualize-time --no-virtualize-metadata` is NOT a remedy — measured, it leaves the guest panicking in timer setup (and, when measured, was rejected outright under `--strict`; it now passes host time through, see https://github.com/rrnewton/hermit/issues/1176); the advisory stopped naming it on 2026-08-21. See `docs/QEMU_BOOT.md`. |

## Unsupported Guest Behavior

| Message | Class | Trigger | Fix |
| --- | --- | --- | --- |
| guest receives `ENOSYS` from `futimesat` | Unsupported | The obsolete `futimesat(2)` syscall is intentionally not implemented. | Update the guest to `utimensat(2)` or `futimens(3)`. `--strace-only` is a compatibility diagnostic, not a deterministic fix. |
| `Not handling deprecated syscall: epoll_wait_old(...)` or `epoll_ctl_old(...)` | Unsupported | A guest used an obsolete pre-2.6 epoll ABI. | Rebuild/update the guest to `epoll_wait`/`epoll_pwait` and `epoll_ctl`. |
| `futex command FUTEX_CMP_REQUEUE_PI is not supported: Detcore does not emulate requeue-PI futexes (PI condition variables)` (also `FUTEX_WAIT_REQUEUE_PI`) | Unsupported | The guest used the requeue-PI pair, which moves a condition variable's waiters onto a priority-inheritance mutex. glibc's condition variables have not issued it since glibc 2.25. A fail-closed run stops with the policy-refusal status (122); with `--allow-unsupported-syscalls` the guest gets `ENOSYS`, as from a Linux kernel built without `CONFIG_FUTEX_PI`. | Wait on the condition variable's own futex and lock the mutex afterwards, as glibc does. FUTEX_WAIT, FUTEX_WAKE, their BITSET forms, FUTEX_REQUEUE, FUTEX_CMP_REQUEUE, FUTEX_WAKE_OP and the priority-inheritance lock commands FUTEX_LOCK_PI, FUTEX_LOCK_PI2, FUTEX_TRYLOCK_PI and FUTEX_UNLOCK_PI are emulated; FUTEX_FD and unknown commands get `ENOSYS`, as on Linux. |
| `futex command FUTEX_WAKE_OP is not supported: its word is in a file-backed shared mapping that a process outside Hermit could update concurrently, and Detcore cannot apply the operation atomically` (also `FUTEX_LOCK_PI`, `FUTEX_LOCK_PI2`, `FUTEX_TRYLOCK_PI`, `FUTEX_UNLOCK_PI`) | Unsupported | The command changes its futex word, and the word lives in a `MAP_SHARED` file mapping (a regular file, `shm_open` or memfd object), which a process Hermit does not run could change between Detcore's read and write. Linux applies these commands atomically. A fail-closed run stops with the policy-refusal status (122); with `--allow-unsupported-syscalls` the guest gets `ENOSYS`. | Keep the futex word (a `PTHREAD_PROCESS_SHARED` mutex) in anonymous `MAP_SHARED` memory shared by `fork`, which Detcore emulates. |
| `futex command FUTEX_LOCK_PI is not supported: the caller is in a nested PID namespace, whose priority-inheritance futex words hold TIDs Detcore does not translate` (also `FUTEX_LOCK_PI2`, `FUTEX_TRYLOCK_PI`, `FUTEX_UNLOCK_PI`) | Unsupported | A thread in a PID namespace the guest created contended a priority-inheritance mutex. Its futex word holds TIDs as that namespace numbers them, and Detcore compares and writes the container namespace's. A fail-closed run stops with the policy-refusal status (122); with `--allow-unsupported-syscalls` the guest gets `ENOSYS`. | Run the program in Hermit's own PID namespace, or use a mutex without `PTHREAD_PRIO_INHERIT`. |
| `futex command FUTEX_REQUEUE is not supported: --debug-futex-mode polling does not model futex waiter lists` (also `FUTEX_CMP_REQUEUE`, `FUTEX_WAKE_OP`, `FUTEX_LOCK_PI`, `FUTEX_LOCK_PI2`, `FUTEX_TRYLOCK_PI`, `FUTEX_UNLOCK_PI`) | Unsupported | The guest requeued futex waiters, used FUTEX_WAKE_OP, or used a priority-inheritance lock command under the polling futex debug mode. | Use the default `--debug-futex-mode precise`, which emulates these commands. |
| `hermit: a signal interrupted Detcore's shared futex key check for word ...; refusing the run rather than retrying it`, exit 122 | Unsupported | A signal arrived at exactly the instruction of the effect-free futex call Detcore injects to ask the kernel whether a shared futex word is a valid key (FUTEX_WAKE, FUTEX_WAKE_BITSET, FUTEX_REQUEUE, FUTEX_CMP_REQUEUE, FUTEX_WAKE_OP or a priority-inheritance lock command on a non-private word). Retrying could lose that signal, and the call has no Linux answer to return, so the run stops whatever the unsupported-syscall policy (https://github.com/rrnewton/hermit/pull/4020). | Rerun; this needs a signal at one exact instruction and is rare. Use `FUTEX_PRIVATE_FLAG` for words that are not shared between processes. |
| `hermit: a POSIX timer expired that notifies with real-time signal N, which Detcore does not deliver from a timer; refusing the run ...`, exit 122 | Unsupported | A `timer_create` timer with a real-time `sigev_signo` (32 to 64, including every glibc `SIGEV_THREAD` timer) reached its expiration under a fail-closed run. Creating, arming, reading and deleting it are supported, and an expiration whose signal is ignored and unblocked is discarded as on Linux; Detcore does not deliver a real-time signal from a timer (https://github.com/rrnewton/hermit/issues/3893), though it delivers one that a thread or process sends (https://github.com/rrnewton/reverie/issues/207). Because virtual time advances to a pending timer when no thread can run, a long watchdog timer around blocking external I/O can reach its deadline and be refused. | Use a standard signal such as `SIGUSR1`, or a thread that sleeps until the deadline, instead of a real-time-signal or `SIGEV_THREAD` timer. `--allow-unsupported-syscalls` runs on, but the expiration is never delivered. |
| `POSIX timer N notifies with real-time signal N, which Detcore does not deliver from a timer; it is armed but will never fire` | Unsupported | The same timer armed under `--allow-unsupported-syscalls`. | As above; a guest that waits for this expiration will time out or hang where Linux delivers it. |
| `process-directed signal N to process P by kill is not supported: the process has N live threads` (or `by rt_sigqueueinfo`, `by pidfd_send_signal`) | Unsupported | A guest sent a process-directed signal (`kill(pid, sig)`, `sigqueue` or `pidfd_send_signal`) to *another* process with two or more live threads, or used `pidfd_send_signal` on its own. Linux gives it to any thread that wants it; Hermit does not model that choice yet (https://github.com/rrnewton/hermit/issues/4034). A fail-closed run stops with the policy-refusal status; `--allow-unsupported-syscalls` returns `ENOSYS`. | Send the signal to one thread with `pthread_kill`/`tgkill`, or send it while the process has one thread. |
| `process-directed signal N to process P by kill is not supported: <reason> (https://github.com/rrnewton/hermit/issues/4034)` (or `by rt_sigqueueinfo`) | Unsupported | A thread sent `kill(getpid(), sig)`, `kill(gettid(), sig)` or `rt_sigqueueinfo` to its *own* process while another thread lives, on ptrace with sequentialized threads, and Hermit cannot prove from the schedule that the sender takes the signal before any other thread runs. ## Analyze And Schedule Search

What `hermit analyze` concludes is not a failure of Hermit, and it does not
exit 125 or print `HERMIT_INTERNAL_FAILURE`: inputs that do not give it what
it needs exit **2**, the "trouble" code of `diff`, `cmp` and `grep`, and an
analysis that concludes that no event decides the outcome has completed and
exits 0. Only a failure to conclude (replay that does not reproduce, a search
that does not converge) exits 125, under a class line that says which. The
class line is the first line on stderr; clap's usage error exits 2 too,
without one. `hermit bisect` verifies its `--good` and `--bad` schedules the
same way and exits the same. Every exit status of `hermit analyze` and

| Message | Class | Trigger | Fix |
| --- | --- | --- | --- |
| `HERMIT_HB_ANCHOR_NEVER_FIRED`, exit 122 | Configuration | A `--happens-before` anchor named a point the guest never reached. A syscall-occurrence anchor counts the thread's calls that match by descriptor number at call time, and counts syscall entries (a restarted call counts again). |
| `happens-before spec ...: anchor '...' | `HERMIT_HB_HOLD_IN_VFORK_CHILD`, exit 122 | Configuration | A `--happens-before` gate would hold a vfork child (for example the child of `posix_spawn`) before it execs. Refused before stdin is read or the guest starts. | Run on a host with working performance counters and keep `--max-timeslice` enabled, or use a version-1 spec, which has no budget. |
| `HERMIT_HB_RELATIVE_ACROSS_IDENTITY_REPLACEMENT`, exit 122 | Unsupported | A non-leader thread execed and took over its process leader's identity while a relative anchor (`from`) or its base was on one of the two threads. Relative-anchor state is not carried across that replacement. | Anchor the relative event on a thread that does not take part in a non-leader exec, or use an absolute anchor. |
| `HERMIT_HB_POSTHOOK_INTERRUPTED`, exit 122 | Unsupported | A syscall that reached a `--happens-before` anchor with `"phase": "posthook"` was interrupted by a signal: Detcore returned an internal restart code (`ERESTARTSYS` and the like). The refusal names the anchors, the thread, its syscall count and the code. | Anchor the edge at the prehook, or on a call that is not interrupted. A call that only a signal handler ends (`pause`, `rt_sigsuspend`, an interrupted `nanosleep`, `select` or `pselect6`) always returns a restart code, so a posthook anchor on it always ends here. |
| `Fatal: Exiting hermit container immediately upon SIGINT` | Configuration | SIGINT arrived while `--sigint-instakill` was enabled. | This is the requested behavior. Rerun without the option if the guest should handle SIGINT. |
| `Could not read backtrace!` | Configuration | A requested stacktrace could not be unwound. | Install matching debug information/unwind support and preserve the executable; omit stacktrace diagnostics if unnecessary. |
| `Failed to open preemption stacktrace log file` | Configuration | `--preemption-stacktrace-log-file` is unwritable. | Correct the path/permissions or remove the file option to log to stderr. |
| `Sequentializing but not virtualizing ... absolute clock_nanosleep ... just yielding` | Unsupported | Serialized scheduling was combined with host time for an absolute sleep Hermit cannot model. | Keep virtual time enabled, or use `--no-sequentialize-threads` only as a nondeterministic compatibility test. |
| `HERMIT_BINDER_EXIT_REPORT_MISSING: a binder call on descriptor ... waited ... ms for the backend to report task ...'s exit complete`, exit 122 | Internal bug | A binder call admitted to run off the guest's turn alone waits, before it is issued, for the final exit report of every thread retired at its exit's commit, so that the kernel's last writes for that thread (its robust list's futex words, its `clear_child_tid` word) are done. The ptrace backend reports a thread's exit once its final wait status arrives; this report never came within 60 s (see `docs/TIMEOUT_LADDER.md`). Under `--allow-unsupported-syscalls` the guest's call fails with `EOPNOTSUPP` instead, and the run goes on. | Report the run with its log, naming the task in the message. |
| `HERMIT_MODEL_DEADLOCK class=deadlock-under-hermit-model`, exit 121 | Configuration | A deadlock under Hermit's model: the scheduler printed one of the `Deadlock detected: ...` reports below and ended the run because no wake Hermit models can reach any remaining thread. This is not a guest result. It is a native hang only when Hermit models every wake the program relies on; past modeling gaps (robust-futex owner death, dash's `sigsuspend`, a raw exit, KVM's `kill`, happens-before re-admission) produced this same report. On ptrace the run is unwound like a `--timeout` and finished, so the output written before the deadlock, `--summary` and a recording are kept. `--verify` does not count it as verified by default: `--verify-allow=success` refuses run 1 (`first_run_rejected`); only an explicit `failure` or `both` compares the runs, and then `verified` means the deadlock repeats, not that it is native. `hermit-verify chaos-stress` stops on it, and an `analyze` trial ending on it fails. Run the program natively or under `--strace-only`: if it does not hang there, report the minimized program as a Hermit bug. | `HERMIT_VIRTUAL_TIMEOUT_WITH_DEBUGGER`, exit 122 | Configuration | `--virtual-timeout` is combined with `--gdbserver` or `--dap-listen`. | `HERMIT_RUN_TIMEOUT class=virtual-timeout bound_ns=N`, exit 124 | Configuration | The run's virtual clock passed `--virtual-timeout=N`: the scheduler printed its `Virtual timeout: at scheduler turn T ...` report and granted no further turn. A caller keys on the class line, not on 124 alone, which `--timeout` (`class=run-timeout`) and a guest may also produce. |
| `HERMIT_DEADLOCK: ...`, then `HERMIT_INTERNAL_FAILURE class=container-child-exit status=Exited(1)`, exit 125 | Internal bug | A scheduler invariant broke (for example a SIGKILL it cannot complete without the thread's pidfd), or a backend never reported a death the kernel owed within the valve. Hermit cannot go on; unlike `HERMIT_MODEL_DEADLOCK` this is not a deadlock verdict at all. | Preserve the command and log and report it. |
| `Deadlock detected: thread(s) waiting on futex, but no runnable threads left` | Configuration | Every modeled thread is asleep on a futex and no modeled wake is possible. | Check the guest synchronization protocol first. | `Deadlock detected: ..., and thread(s) retrying a pipe or socket-pair call no remaining thread can satisfy, but no runnable threads left` | Unsupported | The scheduler finds no modeled source of progress for the remaining waits and exits with Hermit failure status 125. ## Internal Bug Panics

The following message families have no valid user-level fix. Re-run with
`RUST_BACKTRACE=1`, capture `hermit --log=debug --log-file=hermit.log ...`, and
report the exact command, Hermit commit, host kernel/CPU, and smallest guest.
Do not work around them by trusting the output of the failed run.

| Message family | Trigger |
| --- | --- |
| `HERMIT_SCHEDULER_PANIC: the scheduler panicked (above); ...`, then `HERMIT_INTERNAL_FAILURE class=container-child-exit status=Exited(101)` | Detcore's scheduler task panicked (the panic message is printed just above). Every guest thread waits on the scheduler, so the container ends at once with exit status 101 and the run exits 125, instead of hanging until `--timeout`. |
| `LogicalTime::duration_since ... future`, `update_global_time ... before start`, `Attempted to update ... time ... already ...`, or `Trying to extract time for thread ... no entry` | Detcore's logical clock moved backward or lost a registered thread. |
| `Couldn't read clock`, `end_of_timeslice is None`, `Ended time slice ... still beyond`, `Timer invariant broken`, or `Failed to set timer` | PMU/RCB timeslice state violated an invariant or the backend rejected a timer. |
| `Cannot set end of timeslice ... current ... already ...` or `Cannot set RCB end of timeslice` | A replayed preemption point is not later than current thread time. A record edited after recording (preemptions removed) does this by design: replay it with `--replay-edited-preemptions`, which skips slices that already ended. Otherwise it can originate in a mismatched/corrupt preemption record; regenerate it before reporting. |
| `thread time should never go down`, `Global time is before epoch start`, or `bump_global_time ... went backwards` | Global and per-thread logical clocks disagree. |
| `Detcore Default impl should not be called` or `Detcore GlobalState Default impl should not be called` | Reverie initialized Detcore through an invalid default path. |
| `Missing DetPid`, `clone_flags must be set by parent`, `parent ... does not exist in thread_to_leader`, or `no entry for dettid ... next_turns` | Thread creation/lifecycle bookkeeping is inconsistent. |
| `Child thread ... not found in preemption history` | A replay trace lacks a newly created thread. This is a warning with fallback priority; use a matching complete trace. |
| `bad initial_priority`, `bad priority argument`, or `not an acceptable priority value` | A corrupt trace or scheduler bug supplied a priority outside the allowed range. Regenerate the trace once before reporting. |
| `Ivar multiple put exception`, `Ivar ... could not lock`, or `Join failed` | Scheduler synchronization state was poisoned or written twice. |
| `TimedEvents::insert ... already in the set`, `multiple entries for dtid ... in TimedEvents`, or `inner set cannot be empty` | Timed-wait bookkeeping contains duplicates or an impossible empty bucket. |
| `Tried to add ... to runqueue, but it's already present`, tentative-selection assertions, or monotonic-turn assertions | Run-queue transaction state is corrupt. |
| `Requests for more than one resource ... not supported`, `mixed in with other resource requests`, or `multiple resource ids in resource request` | An internal caller composed a resource request the scheduler cannot represent. |
| `pause should never return ... except by interruption`, `futex wake doesn't have a timeout`, or `signal_guest ... nonexistent thread` | An impossible scheduler response or signal target occurred. |
| `signal delivery ... group leader thread has exited` | Signal routing hit an unimplemented exited-leader case. |
| `Failed to get fd`, `invalid syscall / unknown fd`, `cannot simulate nonblocking`, or `sockets/pipes ... physically nonblocking` | Detcore's virtual and physical file-descriptor state disagree. |
| `Expect that when virtualize_metadata, DetFd's stat is populated` | Metadata virtualization lost the file's cached stat record. |
| `PreemptionRecord: cannot re-register`, `before registering thread`, or priority/time assertions | Preemption recording and thread registration are out of order. |
| `Thread state should be explicitly initialized in init_thread_state` | Recorder/replayer thread-local state was requested before initialization. |
| `Serialization is not yet implemented` from `event_stream` | Internal code attempted to serialize an event stream object directly; normal record/replay serializes individual events. |
| Bare `not implemented` or `internal invariant`/`impossible` assertions | An unfinished or supposedly unreachable Detcore path ran. |
| Rust's `called Option::unwrap() on a None value`, `called Result::unwrap() on an Err value`, assertion failure, poisoned-lock panic, or integer overflow | An unchecked internal assumption failed. Use the backtrace's first Hermit frame to identify the subsystem and report it. |

## Coverage And Maintenance

This catalog covers production paths in `hermit-cli`, `detcore`,
`detcore-model`, and `hermit-verify` that:

- return an explicit `anyhow` error or context;
- emit an actionable warning/error;
- return `ENOSYS`/unsupported status from Detcore; or
- panic through `panic!`, `unimplemented!`, `expect`, `unwrap`, assertions, or
  poisoned locks.

Test-only assertions, developer scripts, errors printed by the guest, and the
text of arbitrary OS/I/O errors are excluded. OS errors are reported through
the operation-specific context above; apply their standard remedy (path,
permission, space, process/file limit, or host policy) to the final cause in
the chain.

When adding or changing an error path, search at least:

```bash
rg -n 'bail!|anyhow!|context\(|with_context\(' \
  hermit-cli/src detcore/src detcore-model/src hermit-verify/src
rg -n 'panic!|unimplemented!|todo!|\.expect\(|\.unwrap\(|assert' \
  hermit-cli/src detcore/src detcore-model/src hermit-verify/src
rg -n 'ENOSYS|ENOTSUP|EOPNOTSUPP|warn!|error!|WARNING:|Fatal:' \
  hermit-cli/src detcore/src detcore-model/src hermit-verify/src
```

Also update this file when a message or option name changes. For broader setup
and reproducibility guidance, see [USER_GUIDE.md](USER_GUIDE.md#troubleshooting).
