# Hermit/Reverie 0.4.1

This fix release supports stable Rust installation of `hermit-run`, fixes
Ubuntu's libunwind/LZMA linking, and selects Reverie's wait mode from each
task's original retained handle. The default install includes ptrace and KVM;
third-party integrations remain opt-in.

## Kernel compatibility

Hermit's ptrace path is qualified on Ubuntu 24.04's stock Linux 6.8 kernel.
Linux 6.9 and newer provide `PIDFD_THREAD` for the generic Safeptrace interface,
which permits sibling-thread waits and fails clearly when that support is
unavailable. Hermit selects Native waits and decoding only from an actual
original thread pidfd, retaining the same controller through managed waits,
reservations and exit delivery. Linux 6.8 uses the strict explicit owner-thread
interface. Linux 5.15 is an older-kernel design target, with no qualification
claim yet. See the
[compatibility follow-up](https://github.com/rrnewton/reverie/issues/943).

Native memory operations retain the existing generic SDK contract; further
owner-thread enforcement remains open in
[the memory follow-up](https://github.com/rrnewton/reverie/issues/860).
Optional LiteInst cleanup requires native thread pidfds. If its outer exit
adapter is abandoned after the original driver claims a stop, cleanup retains
that driver and can refuse with `EALREADY`; automatic recovery is not guaranteed.

## Reproducing virtual time

An omitted `--epoch` captures the current host time once at invocation startup.
Hermit reports the exact epoch, its source and `reproduce with --epoch=...`.
Reuse the reported epoch and the same seed to repeat time-dependent output.
Explicit `--epoch` or `HERMIT_EPOCH` values are preserved. Analyzer searches
that choose a random seed also print the `--analyze-seed=...` needed to repeat
the search. See the
[epoch behavior discussion](https://github.com/rrnewton/reverie/issues/946).

## Known limitations and deferred work

- A stock VM can deny physical performance-counter access with `EACCES`. The
  eight SDK controls that require those counters encounter an expected
  environment prerequisite failure, which is not a 0.4.1 release blocker.
  Precise preemption still requires usable hardware counters.
- An exec/callback regression intermittently misses its three-second raw
  `ESRCH` deadline: three of five runs of the unchanged test executable failed
  on stock Linux 6.8. This is tracked as a test gating bug; no plain ptrace
  failure has been demonstrated. See
  [the callback issue](https://github.com/rrnewton/reverie/issues/951).
- Nested KVM qualification is deferred; see
  [the nested KVM issue](https://github.com/rrnewton/reverie/issues/940).
- Published repository URL metadata is retained under the existing owner
  policy; see [the follow-up](https://github.com/rrnewton/hermit/issues/3731).
